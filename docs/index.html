Utcp.AspNetCore

Publish a UTCP manual for AI agents straight from your ASP.NET Core OpenAPI document.

GitHub NuGet utcp.io 
dotnet add package Utcp.AspNetCore

What is UTCP?

UTCP (Universal Tool Calling Protocol) lets AI agents discover tools through a manual and then call them directly over their native protocol, with no wrapper server in between. Utcp.AspNetCore publishes a UTCP v1.1 manual at GET /utcp, built automatically from your app's ASP.NET Core OpenAPI document, so agents can discover and call your HTTP endpoints directly.

Quickstart

1. Install

dotnet add package Utcp.AspNetCore

2. Wire it up

using Utcp.AspNetCore;

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddOpenApi();   // required: Microsoft.AspNetCore.OpenApi
builder.Services.AddUtcp();      // optionally: AddUtcp(o => o.DocumentName = "v2")

var app = builder.Build();

app.MapUtcp("/utcp");            // returns an IEndpointConventionBuilder; chain .AllowAnonymous() etc.

app.Run();

Set an operationId on each endpoint (for example .WithName("GetWeather")). Operations without one are skipped. The /utcp endpoint is excluded from the OpenAPI document.

3. Fetch the manual

curl -s http://localhost:5080/utcp

Example: endpoint → tool

A decorated minimal API endpoint:

app.MapGet("/weather/{city}", (string city, int? days) =>
        TypedResults.Ok(GetForecasts(city, days ?? 3)))
    .WithName("GetWeather")                                     // → tool name
    .WithSummary("Get a multi-day weather forecast for a city") // → description
    .WithTags("Weather");                                       // → tags

record WeatherForecast(string City, DateOnly Date, int TemperatureC, string Summary);

becomes this tool in the /utcp manual (actual output):

{
  "name": "GetWeather",
  "description": "Get a multi-day weather forecast for a city",
  "tags": ["Weather"],
  "inputs": {
    "type": "object",
    "properties": {
      "city": { "type": "string" },
      "days": { "type": "integer", "format": "int32" }
    },
    "required": ["city"]
  },
  "outputs": {
    "type": "array",
    "items": {
      "required": ["city", "date", "temperatureC", "summary"],
      "type": "object",
      "properties": {
        "city": { "type": "string" },
        "date": { "type": "string", "format": "date" },
        "temperatureC": { "type": "integer", "format": "int32" },
        "summary": { "type": "string" }
      }
    }
  },
  "tool_call_template": {
    "name": "GetWeather",
    "call_template_type": "http",
    "url": "http://localhost:5080/weather/{city}",
    "http_method": "GET",
    "content_type": "application/json"
  }
}

The route's {city} stays a placeholder in the tool URL, the optional days query parameter becomes an optional input, and the WeatherForecast[] response type becomes the outputs schema. Add .RequireAuthorization() (with a matching OpenAPI security scheme) and the tool gains an auth block — see Auth schemes.

MVC controllers work too

Attribute-decorated MVC controllers map the same way. Call AddControllers() and MapControllers(), and the OpenAPI document (and so the manual) picks the actions up:

[ApiController]
[Route("products")]
public class ProductsController : ControllerBase
{
    [HttpGet("{id:int}", Name = "GetProduct")]               // Name → operationId → tool name
    [EndpointSummary("Get a product by id")]                 // → description
    [Tags("Products")]                                       // → tags
    [ProducesResponseType<Product>(StatusCodes.Status200OK)] // → outputs
    public IActionResult GetProduct(int id, [FromQuery] bool includePricing = false) =>
        Ok(new Product(id, $"Product {id}", includePricing ? 19.99m : null));
}

public record Product(int Id, string Name, decimal? Price);

becomes this tool (trimmed to name, description, tags, inputs and tool_call_template; actual output otherwise):

{
  "name": "GetProduct",
  "description": "Get a product by id",
  "tags": ["Products"],
  "inputs": {
    "type": "object",
    "properties": {
      "id": { "type": "integer", "format": "int32" },
      "includePricing": { "type": "boolean", "default": false }
    },
    "required": ["id"]
  },
  "tool_call_template": {
    "name": "GetProduct",
    "call_template_type": "http",
    "url": "http://localhost:5080/products/{id}",
    "http_method": "GET",
    "content_type": "application/json"
  }
}

[EndpointName("GetProduct")] works as an alternative to Name = on the route attribute. The outputs schema (the Product record) is omitted from the JSON above for brevity.

OpenAPI → UTCP mapping

OpenAPIUTCP
operationIdtool name (operations without one are skipped)
summary / descriptiontool description
operation tagstool tags
path / query / header parametersinputs.properties (required honored; path params always required)
JSON request bodyinputs.properties.body, with tool_call_template.body_field = "body" and content_type set to the media type
header parameterstool_call_template.header_fields
200 response (else first 2xx) JSON schemaoutputs
path + base URLtool_call_template.url, keeping {param} placeholders; call_template_type is http
security schemeauth (see Auth schemes)

$ref component schemas are inlined so each tool is self-contained.

Auth schemes

Security schemes are read from the operation, else the document; first match wins. <SCHEMEID> is the scheme's component id, uppercased with non-alphanumerics replaced by _ (id Bearer → BEARER_TOKEN). Agents substitute the placeholders; the manual never contains real secrets.

HTTP bearer

{ "auth_type": "api_key", "api_key": "Bearer ${<SCHEMEID>_TOKEN}", "var_name": "Authorization", "location": "header" }

API key in a header

{ "auth_type": "api_key", "api_key": "${<SCHEMEID>_API_KEY}", "var_name": "<scheme Name>", "location": "header" }

API key in the query string

{ "auth_type": "api_key", "api_key": "${<SCHEMEID>_API_KEY}", "var_name": "<scheme Name>", "location": "query" }

Query strings commonly end up in access logs and proxies. Prefer header-based keys in real APIs.

HTTP basic

{ "auth_type": "basic", "username": "${<SCHEMEID>_USERNAME}", "password": "${<SCHEMEID>_PASSWORD}" }

OAuth2 and other schemes are ignored.

Run the sample

dotnet run --project samples/Utcp.Sample.Api
curl -s http://localhost:5080/utcp

The sample exposes seven endpoints:

  • GET /weather/{city}?days=3 (GetWeather): path and query inputs.
  • POST /orders (CreateOrder): JSON body.
  • GET /me (GetCurrentUser): requires JWT bearer auth, so its tool includes the auth block.
  • GET /admin/stats (GetAdminStats): API key in the X-Api-Key header (scheme ApiKeyHeader).
  • GET /reports (GetReports): API key in the api_key query parameter (scheme ApiKeyQuery).
  • GET /products/{id} (GetProduct): MVC controller action, path and query inputs.
  • GET /legacy/export (GetLegacyExport): HTTP Basic (scheme Basic).

Demo credentials (sample only, bound from the DemoAuth configuration section): appsettings.json ships empty values and the handlers fail closed — secured endpoints reject everything until credentials are configured. appsettings.Development.json supplies dev-only values (API key demo-key; basic demo / demo), so they only work when ASPNETCORE_ENVIRONMENT=Development (the default for dotnet run). For anything else, supply your own via user-secrets or environment variables (e.g. DemoAuth__ApiKey).

curl -H "X-Api-Key: demo-key" http://localhost:5080/admin/stats

Securing /utcp & security notes

  • /utcp is anonymous by default and lists all documented operations, including secured ones. If your API surface is sensitive, protect it: 
    app.MapUtcp("/utcp").RequireAuthorization();
  • The manual never contains real tokens. Secured tools emit placeholders such as Bearer ${BEARER_TOKEN} for the agent to substitute.
  • Tool URLs use the OpenAPI document's servers[0].Url when absolute; otherwise they reflect the request's Host header. Behind proxies or on the open internet, add a server entry via a document transformer that sets document.Servers, so an attacker-controlled Host header can't be reflected into the manual.
  • The sample's AddJwtBearer() has no authority/key configuration and is not production-ready; it exists only to demonstrate the security-scheme → UTCP auth mapping.

Limitations

  • HTTP call templates only.
  • Only http bearer/basic and apiKey schemes are mapped. OAuth2 and other schemes are ignored.
  • Operations need an operationId, or they are skipped.
  • Targets .NET 9 and OpenAPI 3.0 documents from Microsoft.AspNetCore.OpenApi.
